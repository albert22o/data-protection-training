## Что делает программа

Программа реализует **алгоритм электронной цифровой подписи (ЭЦП)** на основе криптосистемы **RSA**.
В отличие от шифрования, где цель — скрыть содержание сообщения, подпись служит для **проверки подлинности** и **целостности** данных.

Участвуют два участника:

* **Боб** — владелец ключей.
  Он создаёт **публичный** и **приватный** ключи, подписывает сообщения.
* **Алиса** — получатель.
  Она проверяет, что подпись действительно создана Бобом и сообщение не изменено.

---

### Основная идея RSA-подписи

> Пусть у Боба есть модуль $N = P \times Q$ и ключи $d$ (открытый) и $c$ (закрытый), где:
>
> * $\varphi = (P-1)(Q-1)$,
> * $c \cdot d \equiv 1 \pmod{\varphi}$.
>
> Тогда подпись к сообщению (или его хешу) вычисляется и проверяется по формулам:
>
> * **Создание подписи:**
>   $s = h^c \mod N$
>
> * **Проверка подписи:**
>   $w = s^d \mod N$
>   Подпись верна, если $w = h$.
>
> Здесь $h$ — значение хеш-функции от файла.

---

## 1. Генерация ключей — `cmd_genkeys()`

**Назначение:**
Боб генерирует простые числа, вычисляет параметры RSA и сохраняет ключи в файл.

---

### Алгоритм пошагово

1. **Генерация простых чисел `P` и `Q`:**

   ```cpp
   ll P = generate_prime(min_prime, max_prime);
   ll Q = generate_prime(min_prime, max_prime);
   ```

   * Используется функция `generate_prime()` из `cryptography.cpp`.
   * Простота проверяется вероятностным тестом (например, Миллера–Рабина).
   * Если $P = Q$, подбирается новое $Q$.

2. **Вычисление модуля и функции Эйлера:**

   ```cpp
   ull N = (ull)P * (ull)Q;
   ull phi = (ull)(P - 1) * (ull)(Q - 1);
   ```

3. **Выбор открытого экспонента `d`:**

   * Случайно выбирается число $d$ такое, что $1 < d < \varphi$ и $\gcd(d, \varphi) = 1$.

4. **Вычисление закрытого ключа `c`:**

   ```cpp
   ull c = modinv_via_egcd(d, phi);
   ```

   * `modinv_via_egcd()` использует **расширенный алгоритм Евклида**, который находит $x, y$ такие, что:
     $d \cdot x + \varphi \cdot y = 1$
   * Тогда $c = x \bmod \varphi$.

5. **Сохранение ключей в файл:**

   ```
   P
   Q
   d
   c
   ```

   * $P, Q$ — остаются секретными.
   * $d, N$ — образуют **публичный ключ**.
   * $c$ — используется для создания подписи (приватный ключ).

---

## 2. Создание подписи — `cmd_sign()`

**Назначение:**
Создать цифровую подпись для файла с использованием приватного ключа.

---

### Алгоритм

1. **Вычисление хеша файла:**

   ```cpp
   auto digest = file_sha256(infile);
   ```

   * Используется стандартная библиотека OpenSSL (`<openssl/sha.h>`).
   * Применяется алгоритм **SHA-256** — безопаснее, чем MD5.
   * Хеш представляет собой массив из 32 байт.

2. **Подписание каждого байта хеша:**
   Для каждого байта $h_i$ вычисляется:

   ```cpp
   s_i = (h_i)^c mod N
   ```

   Это соответствует операции $s = h^c \mod N$, но реализовано по-байтово, чтобы избежать длинной арифметики.

3. **Формирование файла подписи (`.sig`):**

   Формат файла:

   ```
   RSAS         (4 байта — сигнатура формата)
   cipher_block (1 байт — длина блока подписи)
   N            (8 байт, little-endian)
   hash_len     (8 байт — длина хеша, обычно 32)
   [данные подписи]
   ```

   Каждая подпись-блок сохраняется в big-endian виде.

   ```cpp
   out.write("RSAS", 4);
   out.put(cipher_block);
   write_le64(out, N);
   write_le64(out, hash_len);
   out.write(sigdata.data(), sigdata.size());
   ```

4. **Результат:**

   * Подпись записывается в отдельный файл `<имя>.sig`.
   * Само сообщение не изменяется.

---

## 3. Проверка подписи — `cmd_verify()`

**Назначение:**
Проверить корректность подписи с использованием публичного ключа.

---

### Алгоритм

1. **Чтение файла подписи:**

   * Проверяется наличие сигнатуры `"RSAS"`.
   * Считываются параметры:

     ```cpp
     cipher_block = fin.get();
     N_in_sig = read_le64(fin);
     hash_len = read_le64(fin);
     ```
   * Проверяется совпадение $N$ из файла подписи и из ключей.

2. **Считывание всех зашифрованных байтов подписи:**

   ```cpp
   fin.read(sigbytes.data(), sigbytes.size());
   ```

3. **Вычисление хеша исходного файла (тем же SHA-256).**

   ```cpp
   auto digest = file_sha256(infile);
   ```

4. **Проверка подписи:**
   Для каждого байта $i$ из хеша:

   ```cpp
   w = (s_i)^d mod N;
   ```

   Сравнивается $w$ с исходным байтом хеша:

   ```cpp
   if (w != digest[i]) signature invalid
   ```

5. **Результат:**

   * Если все байты совпали →
     `Signature is VALID`
   * Иначе →
     `Signature is INVALID`

## 4. Структура ключевых функций

| Функция                   | Назначение                             |
| ------------------------- | -------------------------------------- |
| `generate_prime(min,max)` | Генерация простого числа в диапазоне   |
| `egcd(a,b)`               | Расширенный алгоритм Евклида           |
| `modinv_via_egcd(a,mod)`  | Обратный элемент по модулю             |
| `mod_pow(base,exp,mod)`   | Быстрое возведение в степень по модулю |
| `file_sha256(path)`       | Вычисление SHA-256 хеша                |
| `cmd_sign()`              | Формирование цифровой подписи          |
| `cmd_verify()`            | Проверка подписи                       |

## 5. Пример взаимодействия

| Этап | Участник | Действие                          | Формула                    |
| ---- | -------- | --------------------------------- | -------------------------- |
| 1    | Боб      | Генерирует ключи                  | $N=P⋅Q$, $φ=(P−1)(Q−1)$    |
| 2    | Боб      | Находит $d$ и $c=d^{-1} \bmod φ$  | —                          |
| 3    | Боб      | Вычисляет хеш файла $h$           | SHA-256                    |
| 4    | Боб      | Создаёт подпись $s=h^c \bmod N$   | cmd_sign                   |
| 5    | Алиса    | Проверяет подпись $w=s^d \bmod N$ | cmd_verify                 |
| 6    | Алиса    | Сравнивает $w$ и $h$              | если равны → подпись верна |

---

## 6. Основные принципы RSA-подписи

1. **Односторонность:**
   Найти $c$ по $d$ и $N$ невозможно без разложения $N$ на $P$ и $Q$.

2. **Проверяемость:**
   Любой, зная $d$ и $N$, может убедиться, что подпись создана владельцем $c$.

3. **Целостность:**
   Изменение даже одного байта в исходном файле изменит хеш, и проверка не пройдёт.

4. **Неотказуемость:**
   Только владелец приватного ключа $c$ может создать корректную подпись.

---

## 7. Пример работы программы

```bash
# 1. Генерация ключей
./rsasign genkeys bob.key 1000 20000

# 2. Подпись файла
./rsasign sign report.txt report.sig bob.key

# 3. Проверка подписи
./rsasign verify report.txt report.sig bob.key
```

**Вывод:**

```
signature written to report.sig
Signature is VALID
```
